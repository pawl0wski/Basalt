# Tauri fs/dialog/persisted-scope registration (Phase 2a step 1)

## Done

- `basalt-app/src-tauri/Cargo.toml`: `tauri-plugin-fs` (`watch` feature), `tauri-plugin-dialog`, `tauri-plugin-persisted-scope`, all `"2"` like the existing opener entry. `lib.rs`: three `.plugin(...::init())` lines only.
- `capabilities/default.json`: `core:window:allow-destroy`, `dialog:allow-open`, the ten `fs:allow-*` entries from the spec, and `fs:scope` allowing only `$APPCONFIG/basalt.json`. No `$HOME/**`.
- npm: `@tauri-apps/plugin-fs@^2.7.1` and `@tauri-apps/plugin-dialog@^2.8.4` in `packages/app` (the package that will hold the adapters). Both require `@tauri-apps/api ^2.12.0`; installed api is 2.12.4 and Cargo.lock has `tauri` 2.12.4.

## Verified

- `core:window:allow-destroy` exists in tauri 2.12.4 (`crates/tauri/permissions/window/autogenerated/reference.md`); it is NOT in `core:default`, so it must be listed. `Window.destroy()` and `onCloseRequested` exist in `@tauri-apps/api` 2.12.4.
- `npm run typecheck`, `npm run lint`, `npm test` (41 files, 448 tests), `prettier --check` pass.

## NOT verified (environment limits)

- The sandbox has cargo 1.65 / rustc 1.63 (no edition 2024, no rustfmt/clippy) and no webkit2gtk, so `cargo check`, `rust:fmt`, `rust:lint` could not run, `Cargo.lock` was NOT updated (run `cargo update -p tauri-plugin-fs ...`/`cargo check` on a machine with a current toolchain and commit the lock), and `src-tauri/gen/schemas` does not exist, so the capability JSON was not validated against the generated schema. Permission identifiers were checked against the docs only; `fs:scope` and the `fs:allow-*` names must be confirmed by the first real `tauri build`/`dev`.
- Runtime assumptions, all UNVERIFIED: dialog `open` extends the fs scope for a picked directory; persisted-scope keeps it after restart; plugin-fs refuses symlink escapes; `lstat` reports symlinks without following; rename within scope replaces atomically on Windows and Linux; recursive `watch` works on a runtime-scoped directory and reports root deletion; the close guard works with `allow-destroy` alone. No Windows or GUI check was possible.

## Gotchas / open

- `$APPCONFIG/basalt.json` as the only build-time scope does not cover the directory `$APPCONFIG` itself (needed by `mkdir`) or a temp file for atomic writes/`remove` cleanup (e.g. `basalt.json.tmp`). Likely needs `$APPCONFIG` and a temp pattern; decide during the real-device spike.
- `npm install` with the local npm dropped `"peer": true` flags from unrelated entries in `package-lock.json`; harmless, but expect the same diff noise.
- Registering `persisted-scope` after `fs` and `dialog` is recommended by the plugin docs; keep that order.
