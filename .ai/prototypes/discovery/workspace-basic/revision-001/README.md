## How to open and reset

Open `index.html` from this folder in a browser (a `file://` URL is enough; no server, no network). The "Reset simulation" button at the top restores the start: closes the workspace, removes created notes and open tabs, clears errors and resets the Test state. It announces the reset in the status line. All state lives in memory, so reloading the page also resets it.

## Browser checks

- Provider: `playwright` (`.ai/browsers/playwright.md`). Deviation: `basalt-app` has no `node_modules`, so the repository runner could not be used. The walk ran with the Playwright 1.64.1 and Chromium already installed globally on this machine (the repo pins the same `^1.64.1`). Nothing was installed. The throwaway script lives outside the repository and is not part of this revision.
- Page opened as `file://` in a fresh isolated context at 1280x800; narrow check at 375x800. All requests were recorded and only the local `index.html` was requested.
- Evidence is in `evidence/` (screenshots and `browser-results.json`). The results below come from the last of two walks. The first walk reported 8 failures: 6 were errors in the walk script (a locator that also matched the "Close …" buttons, and wrong expected tab counts that cascaded), and 2 were prototype defects fixed in this revision before the last walk:
  1. The modal backdrop covered "Reset simulation" and the Test state controls, so they could not be clicked while a dialog was open.
  2. After "Discard changes", the "Closed …" announcement replaced the "Discarded unsaved changes" announcement within 30 ms. They are now one message.
- Cleanup: the browser context and browser were closed (`CLOSED` printed by the script).

## Static review

- Every action in the confirmed flow has a destination and an expected state (the table above). Edge states included: empty workspace, picker cancel, invalid and taken names, failed save with banner, Save-failed dialog with Retry, Discard and Cancel, unknown address.
- No rule, non-goal or decision changed. The UI carries no persona-coaching text and no research conclusion.
- Checked in `index.html` by search and reading: one inline script and one inline style; no external URL, `fetch`, XHR, web storage, cookie, `innerHTML`, `eval`, `<link>`, `<img>` or form `action`. The only form handler calls `preventDefault`. User text goes into text nodes or `value`.
- Semantics: one `h1` per screen, labelled fields, buttons for actions, a real link for "Go to Welcome", `role="alertdialog"` and `aria-modal` on dialogs, the page behind a dialog is `inert`, status line is a polite live region, a visible 3 px focus outline.
- All data is fictitious (workspace and note names, text).
- Output stays inside `.ai/prototypes/discovery/workspace-basic/revision-001/`. The brief, the screen map, the specs, application code and `.uxproof/` (absent) were not touched.

## What this does not establish

The flow was chosen and its choices were confirmed by the person running the skill. No user was observed. The prototype shows that the sequence can be operated, not that it is the right one. The open product choices behind AS-03 to AS-06 and AS-11 still need an owner decision before an S04 or tabs spec.
