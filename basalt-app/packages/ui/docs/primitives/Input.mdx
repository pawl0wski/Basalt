# Input

## 1. What it is for

An input lets the user type a short piece of text, such as a workspace name or a note title.

<Canvas of={InputStories.Playground} />

## 2. When to use

- A single line of text: names, titles, folder names, search text.
- Always inside a [Field](?path=/docs/primitives-field--docs) when it is part of a form, so it has a visible label.

## 3. When not to use

| Situation | Use instead |
|---|---|
| The user picks from a short fixed list. | Select or RadioGroup (Batches 2 and 3). |
| The user turns something on or off. | Switch or [Checkbox](?path=/docs/primitives-checkbox--docs). |
| The text has many lines. | A multi-line text area. It is not part of the current plan; see "What is missing". |
| The user edits a note. | The note editor, not a form control. |

## 4. Anatomy

1. Field box: 28 px high (`h-icon-button`), `rounded-control`, 1 px `border-control` (3:1 against the surface, WCAG 1.4.11), `surface-frame` fill.
2. Text: `text-size-ui` in `text-ui`.
3. Placeholder: `text-muted`. Optional.
4. Label, hint and error come from the surrounding Field. The Input has none of its own.

## 5. Variants

One variant. Type is set with the native `type` prop (`text` by default). Other types (`email`, `search`) are not styled differently. Adding a variant needs a second use in the product.

## 6. States

| State | What the user sees | Notes |
|---|---|---|
| Default | `border-control` outline, `text-ui` text. | |
| Hover | No change. The text cursor already shows it is editable. | Proposal. |
| Focus | 2 px `focus-ring` outline, 2 px offset (also on mouse focus, as the user is about to type). | |
| Filled | Same as default. | |
| Invalid | `status-danger` border, plus an error message in the Field. Color is never the only signal: the message carries the meaning (WCAG 1.4.1). | Set `aria-invalid`. |
| Disabled | `text-muted` text on `state-hover`. | Proposal (open question 3). Explain why in the hint. |
| Loading | Not supported. | |

## 7. Behavior and accessibility

- Native `input`. The accessible name must come from a visible label (Field) or, when there is no room for one such as a search field with an icon, an `aria-label`.
- Never use the placeholder as the label: it disappears while typing and has weaker contrast (WCAG 3.3.2).
- Inside a Field the Input receives `id`, `aria-describedby`, `aria-invalid` and `aria-required` automatically. Outside a Field, pass them yourself.
- Keyboard: Tab focuses, typing edits. Enter submits the surrounding form.
- Height 28 px, above the 24 px target minimum (WCAG 2.5.8).

## 8. Content

- Placeholder: an example value ("Personal notes"), never an instruction and never the field name.
- Do not prefill with fake data; use `defaultValue` only for real values.
- Long values scroll horizontally inside the box; the box never grows.

## 9. Responsiveness

The input fills the width of its container (`w-full`). Limit the container, not the input, on wide screens: use `max-w-prose` (65 characters) for form columns.

## 10. API

| Prop | Type | Default | Description |
|---|---|---|---|
| `type` | `string` | `"text"` | Native input type. |
| `aria-invalid` | `boolean` | set by Field | Switches on the error style. |
| `disabled` | `boolean` | `false` | Blocks input. |
| `ref` | `Ref<HTMLInputElement>` | | Forwarded to the element (React 19). |
| ...rest | `InputHTMLAttributes` | | Passed to the element, including `value`, `onChange`, `placeholder`. |

## 11. Code

```tsx
import { Field, Input } from "@basalt/ui";

<Field label="Workspace name" hint="Shown in the window title.">
    <Input placeholder="Personal notes" />
</Field>
```

```tsx
<Input aria-label="Search notes" type="search" />
```
